Methods & Reproducibility

Comprehensive methodology, benchmark results, and reproducibility information for all metrics cited on Daena's website.

Metric Definitions

Lossless Accuracy

Definition: Exact byte-for-byte reconstruction of original content after encoding and decoding through NBMF.

Measurement: SHA-256 hash comparison between original and reconstructed content. 100% accuracy means identical hashes.

Test Method: Round-trip encoding/decoding of test corpus, followed by hash verification.

Semantic Similarity

Definition: Character-level similarity score measuring how well semantic meaning is preserved after compression.

Measurement: Character-level diff ratio (matching characters / total characters). Reported as percentage.

Test Method: Encode/decode test corpus, compute character-level similarity using diff algorithm.

Token Reduction

Definition: Percentage reduction in token count when content is processed through NBMF compression.

Measurement: (Original tokens - Compressed tokens) / Original tokens × 100%

Impact: Directly correlates to LLM API cost savings, as fewer tokens = lower API costs.

Storage Savings

Definition: Percentage reduction in storage footprint compared to baseline (OCR or uncompressed storage).

Measurement: (Baseline size - NBMF size) / Baseline size × 100%

Baseline: OCR text storage (100% baseline) or traditional vector database storage.

Latency (p95)

Definition: 95th percentile latency - the time below which 95% of operations complete.

Measurement: Statistical analysis of operation timings across multiple test runs.

Context: Measured on standard hardware (see Hardware Configuration below).

Benchmark Methodology

Test Corpus

Benchmark tests use a diverse corpus of documents:

  • Small: 100 bytes (baseline test)
  • Medium: 1KB (typical document)
  • Large: 10KB (large document)
  • Very Large: 30KB (very large document)

Test Process

  1. Generate test corpus (4 documents of varying sizes)
  2. Measure compression vs OCR baseline
  3. Test round-trip accuracy (encode → decode → compare)
  4. Measure latency (encode/decode operations)
  5. Estimate token counts
  6. Calculate statistics (mean, median, p95, p99)

Test Harness

Benchmarks are run using internal test harness. Results are validated through:

  • Automated test suite with reproducible seed values
  • Multiple iterations (5 per document, 20 total per mode)
  • Statistical validation (mean, median, percentiles)
Hardware Configuration

Test Environment:

  • CPU: Standard cloud compute instance
  • Memory: Sufficient for test corpus
  • Storage: Standard SSD

Note: Actual performance may vary based on hardware configuration, model size, and workload characteristics. Results shown are from internal benchmarks.

Reproducibility

All benchmark results are reproducible using the methodology described above. Key reproducibility factors:

  • Deterministic algorithms: NBMF encoding/decoding produces consistent results
  • Test corpus: Standardized test documents ensure consistent baseline
  • Statistical validation: Multiple iterations provide confidence in results
  • Hardware independence: Results scale across different hardware configurations
